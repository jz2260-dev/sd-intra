Image and Configure Windows Laptop (MDT)

Standard NYU laptop imaging workflow for MDT-based Windows 11 builds, with clear go or no-go checks, local user setup, validation, and final asset updates.

SOP Flow

Start with imaging readiness, confirm the laptop should stay on the MDT path, complete the build, then close with validation and record updates.

Overview

Use this SOP for standard NYU laptop imaging through MDT.

Primary outcomeDeliver a fully imaged Windows 11 laptop with local user setup, required agents reporting, and asset records updated.
Use whenThe device is a supported laptop and can boot cleanly to MDT over a USB NIC path.
Do not use whenMDT repeatedly fails, network boot is unsupported, or hardware requires the KACE fallback path.

Prerequisites

Confirm these before you begin imaging.

Supported laptop connected to power and stable network.

USB NIC available and recognized by the device.

NYU credentials available for the MDT deployment share.

Expected computer naming convention confirmed before deployment starts.

Decision Points

Use these checks to stay on the right path.

Can the laptop PXE or USB-NIC boot into MDT?If yes, continue with this SOP. If no, stop and review BIOS settings or move to the KACE SOP if the failure persists.
Is MAC Address Pass-Through enabled?Disable it before retrying the network boot path on supported hardware.
Did the first-login automation run?If not, complete the manual recovery step before moving on to user setup and validation.

Procedure

Primary imaging sequence for NYU laptops.

1
Prepare BIOS and boot pathEnter BIOS with F2, enable UEFI Network Stack, disable MAC Address Pass-Through if available, save, and restart.
2
Start MDT deploymentPress F12, choose USB NIC (IPv4), authenticate with NYU credentials, and launch Deploy Staff PC -- Windows 11 25H2.
3
Set deployment choicesEnter the computer name, choose Join Workgroup, keep the workgroup as Workgroup, select Adobe only if required, and begin imaging.
4
Complete administrator passAfter imaging, sign in as Administrator, allow the script to run, and restart. If the script does not run, use C:\scripts\FirstLogin.bat.
5
Create and validate the user accountCreate the local NetID user, add the account to local Administrators, sign in as the user, allow the user-side script to run, restart, and sign back in.
6
Standardize apps and reportingSet Chrome, Edge, and Firefox to sternlife.stern.nyu.edu, complete Windows and app updates, then run KACE, InsightVM, and Cortex XDR check-ins.

Validation and Closeout

Use these checks before handoff.

ActivationWindows and Office activate successfully.
User sign-inThe local NetID user can sign in and has the expected admin membership.
StandardsBrowsers, Zoom, and required updates are complete.
ReportingKACE, InsightVM, and Cortex XDR are all checking in.
Asset recordsKACE labels and Salesforce (E360) assignment are updated correctly.
Password handlingRequire password change at next login once the handoff is ready.

Escalation and Recovery

Escalate instead of forcing the build when these happen.

MDT boot keeps failingRecheck BIOS, USB NIC path, and network stack. If the path still fails, move to the KACE fallback procedure.
Script or activation failureUse the documented manual recovery step once, then escalate rather than rebuilding immediately.
Asset or security tools not reportingHold the handoff until KACE, InsightVM, Cortex XDR, and E360 are corrected.
