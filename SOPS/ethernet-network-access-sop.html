SOP - Internal Procedure

Ethernet and Network Access Support

Use this SOP to validate MAC address, VLAN, and DNS Manager updates, then confirm wired connectivity for Stern-supported devices.

SOP Flow

Review the request, confirm the physical path, collect the MAC address, set the right VLAN entry, and validate wired access before closing.

Overview

Use this SOP for Ethernet access requests, VLAN changes, and no-network troubleshooting on wired devices.

Primary outcomeThe device is assigned to the correct VLAN and has verified wired network connectivity.
Use whenThe issue involves Windows or Apple devices needing Ethernet access or DNS Manager updates.
Do not use whenThe request is clearly Wi-Fi-only or requires advanced infrastructure troubleshooting beyond the desk-side flow.

Prerequisites

Confirm these before changing network records.

Request includes device type and physical location.

Device is connected via Ethernet or adapter path can be tested.

MAC address can be collected from the correct wired interface.

Wall port, jack, or desk phone state can be checked if needed.

Decision Points

Use these checks before you change VLAN or DNS records.

Do you have the correct wired MAC address?If not, stop and verify the interface before making any network change.
Is the VLAN different from the default?If yes, confirm location, department, or use case before updating DNS Manager.
Is the desk phone also offline?If yes, suspect a location or jack issue rather than only a device registration problem.

Procedure

Standard wired network support sequence.

1
Review the requestConfirm the user, device type, location, and whether the issue is new access, no connectivity, or VLAN change.
2
Validate the physical pathConfirm the device is physically connected through the intended Ethernet cable, adapter, and wall port.
3
Collect the MAC addressOn Windows use ipconfig /all. On macOS use System Settings or ifconfig to identify the correct Ethernet MAC.
4
Determine the VLANUse VLAN 11 by default unless location, department, or use case requires a different assignment.
5
Update DNS ManagerAdd or update the DNS Manager entry with MAC address, hostname if known, and the correct VLAN assignment.
6
Validate connectivityConfirm IP assignment, internet access, internal resource access, and if useful, compare against desk phone connectivity at the same location.

Validation and Closeout

Use these checks before marking the request complete.

Device recordThe correct wired MAC address was used.
VLANThe intended VLAN assignment is confirmed.
DNS updateThe DNS Manager record was added or corrected.
ConnectivityThe device receives an IP and reaches required resources.
Location checkDesk phone or jack behavior was considered when relevant.
DocumentationTicket notes include MAC, VLAN, location, and validation results.

Escalation and Recovery

Escalate when the issue is likely beyond a standard registration update.

Correct MAC and VLAN still do not restore accessEscalate to Endpoint Management with MAC, location, VLAN, and validation details.
Phone and endpoint both fail at the same locationTreat this as a likely port or infrastructure issue and escalate with jack details.
VLAN is unclear or nonstandardDo not guess. Escalate before applying an uncertain network assignment.
