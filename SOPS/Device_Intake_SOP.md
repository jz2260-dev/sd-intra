# Device Intake / Request Handling SOP

---

## Quick Start (Use This First)

Follow this checklist for all device-related requests:

- [ ] Identify intake method:
  - Walk-in (Release Form)
  - Salesforce request
  - Email-generated ticket  
- [ ] Confirm request type (New Device, Reimage)  
- [ ] Verify required information and approvals  
- [ ] Confirm user and device details  
- [ ] Confirm data responsibility (if applicable)  
- [ ] Route to correct workflow:
  - Laptop Imaging SOP  
  - Desktop Imaging SOP  
- [ ] Update ticket with notes and status  

If anything is missing, stop and clarify before proceeding.

---

## Intake Methods

### 1. Walk-In / Drop-Off (Release Form)

Use when a user physically brings a device to the Service Desk.

#### Required Steps

- Ensure release form is completed and signed  
- Verify:
  - User information (NetID, department)  
  - Device details (serial, model)  
  - Usage type (individual or shared)  
  - Support type selected  

#### Critical Notes

- User acknowledges:
  - IT is not responsible for data preservation  
  - Device may be wiped or factory reset  
  - Backup is the user's responsibility  

- Confirm:
  - Charger is included  
  - Device is accepted into intake by the Service Desk  

---

### 2. Salesforce Intake (New Devices)

Use for:
- New device provisioning  
- Lifecycle refresh  

#### Required Steps

- Review Salesforce record  
- Verify:
  - Device type (Laptop/Desktop)  
  - User assignment  
  - Department  
- Confirm approvals (if applicable)  

---

### 3. Email Intake (Auto-Ticket)

Use when:
- User emails the Service Desk → ticket is automatically created  

#### Required Steps

- Review ticket content  
- Identify missing details:
  - Device type  
  - Request type  
  - Urgency  

- Follow up with user if unclear  

---

## Step-by-Step (Standard Process)

### 1. Identify Request Type

| Request Type | Action |
|--------------|--------|
| New Device | Prepare and image new device |
| Reimage | Reimage existing device |

---

### 2. Validate Requirements

Verify:

- User identity (NetID)  
- Device type  
- Department  
- Approval (if required)  

If missing:
- Contact requestor before proceeding  

---

### 3. Data Responsibility Check

For reimage or repair:

- Confirm user understands:
  - Data may be lost  
  - Backup is their responsibility  

If walk-in:
- Covered by signed release form  

If ticket/email:
- Add confirmation note in ticket  

---

### 4. Route Work

Proceed with:

- Laptop → Laptop Imaging SOP  
- Desktop → Desktop Imaging SOP  

If escalation is required:
- Assign to Endpoint Management  

---

### 5. Track and Update Ticket

Update ticket with:

- Intake method (Walk-in / Salesforce / Email)  
- Request type (New Device / Reimage)  
- Device details (type, serial if applicable)  
- Actions taken  

Update status:

- In Progress  
- Awaiting Information  
- Completed  

---

### 6. User Communication

Notify user:

- When device is received  
- When work begins  
- When device is ready  

---

## Something Went Wrong (Quick Fixes)

| Issue | What to Check |
|------|---------------|
| No release form | Do not accept device |
| Missing information | Request details from user |
| No approval | Hold request |
| Unclear request | Clarify before proceeding |
| Data loss concern | Confirm acknowledgment |

---

## Done When

- Request is validated  
- Device is routed or completed  
- Ticket is fully documented  
- User has been notified  

---

## Notes for Technicians

- Intake quality determines outcome quality  
- Never skip validation steps  
- Always confirm data responsibility  
- Use imaging SOPs for execution  
- Escalate to Endpoint Management when required
