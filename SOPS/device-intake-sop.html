SOP Flow

Confirm how the request arrived, validate details and approvals, document data responsibility, then route the work into the correct device workflow.

Overview

Use this SOP for all new device, reimage, and walk-in device intake requests.

Primary outcomeRequests are accepted only when information, approvals, and risk acknowledgments are complete.
Use whenA device request comes in through walk-in intake, Salesforce, or email-generated ticket.
Do not use whenThe work is already validated and actively in imaging or advanced endpoint troubleshooting.

Prerequisites

Confirm these before formally accepting or routing the request.

Intake source is known: walk-in, Salesforce, or email-generated ticket.

User identity, department, and request type are captured.

Required approvals are present or identified as missing.

Data responsibility has been acknowledged for reimage or repair work.

Decision Points

Use these checks before moving the request forward.

Is the request complete enough to accept?If required information is missing, pause and clarify before routing or starting work.
Is this a new device or reimage?Use that answer to choose the downstream SOP and confirm data risk communication.
Was a release form required?Do not accept a walk-in device without the signed release form and basic hardware details.

Procedure

Standard intake and routing sequence.

1
Identify the intake methodDetermine whether the request arrived by walk-in release form, Salesforce request, or email-generated ticket.
2
Validate the request typeConfirm whether the work is a new device request or a reimage of existing hardware.
3
Confirm required details and approvalsVerify NetID, department, device type, serial or model if applicable, and any required approvals before continuing.
4
Document data responsibilityFor reimage or repair work, confirm the user understands that backup is their responsibility and that the device may be wiped or reset.
5
Route the workSend laptop work to the laptop imaging SOP, desktop work to the desktop imaging SOP, or escalate to Endpoint Management if the request is outside standard handling.
6
Update the ticket and user communicationDocument intake source, request type, device details, actions taken, current status, and user-facing updates.

Validation and Closeout

Use these checks before closing the intake stage.

Intake sourceThe request source is documented correctly.
Request detailsUser, device, department, and request type are complete.
ApprovalsRequired approvals are present or the request is held appropriately.
Data acknowledgmentBackup and wipe responsibility are documented when relevant.
RoutingThe request is sent to the correct downstream workflow.
Ticket notesStatus and actions taken are recorded clearly.

Escalation and Recovery

Escalate when request quality or authority is insufficient.

No release form or required approvalHold the request and do not accept or proceed until the missing requirement is resolved.
Request is unclear or contradictoryClarify with the user or manager before routing the device.
Workflow does not fit standard imaging pathsEscalate to Endpoint Management with intake notes and device context.
