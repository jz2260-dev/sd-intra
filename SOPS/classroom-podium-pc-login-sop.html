SOP - Internal Procedure

Classroom Podium PC Login Support

Use this SOP to restore podium PC access quickly, validate classroom readiness, and decide when to use the local fallback account or escalate.

Overview Prerequisites Decision Points Procedure Validation Escalation

SOP Flow

Wake the podium, confirm the login path, validate classroom tools, and use the local contingency path only when time-sensitive access is blocked.

Overview

Use this SOP when supporting podium PC logins in classrooms or event spaces.

Primary outcomeRestore user access and confirm the podium is ready for presentation or instruction.
Use whenThe issue involves classroom podium PC login, profile load, or immediate classroom functionality.
Do not use whenThe issue is clearly projector-only, network-only, or a persistent domain problem requiring Endpoint Management.

Prerequisites

Confirm these before troubleshooting the login path.

Podium PC is powered on or can be woken from sleep.

Monitor, keyboard, mouse, and projector or display path are active.

User has NYU credentials available.

Room location is known in case escalation is needed.

Decision Points

Use these checks to choose the fastest safe path.

Is the Windows login screen visible?If not, restore power, display, or device wake state before testing credentials.
Is class or an event starting immediately?If time is critical and standard login fails, use the local .\tutor account as the contingency path.
Is this likely a first-time login?If yes, allow extra time for profile creation before assuming the login is stuck.

Procedure

Standard podium login support sequence.

1
Wake or power on the podiumPower on or wake the device and confirm the monitor and attached peripherals are active.
2
Confirm the login screenVerify the Windows login screen is visible and the device appears domain-connected.
3
Test the user loginHave the user enter NetID and NYU password, then allow the login to process fully.
4
Allow first-time profile creation if neededIf the user has not signed into this podium before, allow several minutes for the profile to build.
5
Validate classroom basicsConfirm internet access, browser launch, presentation software, and the display or projector path.
6
Use testing closeout when appropriateIf the login was only for validation, log out after confirming podium readiness.

Validation and Closeout

Use these checks before leaving the classroom.

User accessThe user can log in successfully.
Desktop loadThe desktop opens with no login or profile errors.
NetworkInternet access is working on the podium.
Presentation toolsBrowser and presentation software launch correctly.
Display pathProjector or classroom display output is functioning.

Escalation and Recovery

Escalate when the issue is larger than a quick podium recovery.

User cannot log in after credential validationConfirm AD path and escalate to Endpoint Management with room, device, NetID, and error details.
No network or domain behaviorFollow the network access SOP or escalate with connectivity details.
Class is starting and standard login is blockedUse .\tutor as the immediate contingency, then document and escalate the persistent issue.
