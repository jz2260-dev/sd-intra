SOP - Internal Procedure

Image and Configure Windows Device (KACE)

Fallback imaging procedure for non-standard or unsupported Windows hardware when MDT cannot be used successfully.

Owner
Stern IT Service Desk
Last reviewed
August 4, 2026
Overview Prerequisites Decision Points Procedure Validation Escalation

SOP Flow

This is the fallback path. Confirm MDT is not viable first, then proceed through KACE registration, deployment, validation, and asset updates.

Overview

Use this SOP only as the fallback imaging path when MDT is not viable.

Primary outcomeRecover a non-standard Windows device through KACE-managed imaging and return it to a supported handoff state.
Use whenUnsupported hardware, missing drivers, or repeated MDT failure blocks the standard path.
Do not use whenThe device can still complete the MDT flow with standard recovery checks.

Prerequisites

Confirm these before moving off the MDT path.

MDT path already attempted or ruled out for a documented reason.

Device is connected to Ethernet and can reach KACE services.

Local administrator path is available for agent install and recovery steps.

Device model and failure context are documented before escalation or fallback imaging.

Decision Points

Use these checks before committing to the fallback path.

Did MDT fail for a real hardware reason?If yes, continue here. If the issue was only a missed BIOS or network setting, correct MDT first.
Can the device register in KACE?If not, stop and resolve network or agent health before assuming the fallback imaging will complete.
Are drivers still missing after KACE?Use manufacturer recovery only as a targeted repair, then escalate if the endpoint still cannot reach standard state.

Procedure

Fallback imaging sequence for unsupported devices.

1
Prepare the deviceEnter BIOS with F2, disable MAC Address Pass-Through, enable UEFI Network Stack, then save and restart.
2
Reach local setupBoot to Windows setup. If needed, use installation media. At the network requirement screen, press CTRL + SHIFT + F10, run oobe\bypassnro, and let the device restart.
3
Create a local admin pathContinue with limited setup, create a local administrator account, and do not use a Microsoft account.
4
Register with KACEConnect via Ethernet, install the KACE agent, navigate to C:\Program Files\Quest\Kace, and run runkbot 4 0.
5
Launch the fallback image taskConfirm the device appears correctly in KACE, then run the Deploy Windows 11 Image task chain from the KACE admin console.

Post-Imaging Validation

Use these checks to confirm the fallback build is actually ready.

Driver healthNetwork and core device drivers are functioning after deployment.
Apps and licensingKACE-installed apps open correctly and Office licensing is active.
Security reportingKACE, Cortex XDR, and InsightVM are reporting successfully.
Asset updatesKACE labels, user assignment, and Salesforce (E360) ownership details are updated.

Escalation Criteria

Bring in Endpoint Management when the fallback path itself starts breaking down.

Device still unsupported after enrollmentEscalate with the device model, BIOS state, and exact KACE results.
KACE agent installs but never registersStop the workflow and escalate after confirming Ethernet and agent path.
Task chain fails or image is incompleteRetry once if appropriate, then escalate instead of layering manual fixes.
Core drivers remain missingEscalate to Endpoint Management with the hardware model and driver gap details.

Escalate to Endpoint Management with the device model, KACE status, and the exact steps already performed.
