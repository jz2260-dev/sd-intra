Image and Configure Windows Desktop (MDT)

Standard NYU desktop imaging workflow for MDT-based Windows 11 deployments, with clear setup decisions, post-image validation, and asset handoff.

SOP Flow

Confirm the desktop is suitable for MDT, complete the build path, then close with validation, DNS, and asset record updates.

Overview

Use this SOP for standard NYU desktop imaging through MDT.

Primary outcomeDeliver a domain-ready desktop with validated imaging, user setup, updates, and correctly recorded network and asset data.
Use whenThe desktop can boot reliably to MDT over the onboard NIC path.
Do not use whenThe device cannot sustain the MDT path or requires unsupported hardware handling.

Prerequisites

Confirm these before imaging starts.

Supported desktop connected to stable Ethernet.

Expected computer name and destination OU confirmed.

NYU credentials available for MDT authentication.

DNS or VLAN expectations known before handoff.

Decision Points

Use these checkpoints to avoid rework.

Can the device boot from the onboard NIC?If yes, stay on the MDT path. If no, stop and correct BIOS or physical network issues first.
Is the final OU known?If not, use OU-STAGING and flag the follow-up rather than guessing the destination.
Did post-image automation fail?Run the documented recovery step once, then escalate if the build still does not stabilize.

Procedure

End-to-end desktop imaging sequence.

1
Prepare BIOS and network bootRestart the desktop, enter BIOS with F2, enable UEFI Network Stack, save, and restart.
2
Launch MDT deploymentPress F12, choose Onboard NIC (IPv4), authenticate with NYU credentials, and start Deploy Staff PC -- Windows 11 25H2.
3
Set naming and OUName the machine using SSB-[Serial Tag], choose the correct department OU, and use OU-STAGING if the destination is unclear.
4
Complete administrator passSign in as Administrator, retrieve the password from PAM if needed, allow the script to run, and restart. If needed, run C:\scripts\FirstLoginAdmin.bat.
5
Apply standards and updatesConfirm Windows and Office activation, add the user's NetID to local Administrators, set browser homepages to sternlife.stern.nyu.edu, and complete Windows, Zoom, browser, and application updates.
6
Run reporting and network updatesRun KACE, InsightVM, and Cortex XDR check-ins, then record MAC and DNS details with the correct VLAN before handoff.

Validation and Closeout

Use these checks before handing off the desktop.

ActivationWindows and Office are activated.
User accessThe assigned user can sign in and has the right local permissions.
StandardsBrowsers, Zoom, and core apps match the expected desktop standard.
ReportingKACE, InsightVM, and Cortex XDR are reporting correctly.
Network recordsMAC, DNS, and VLAN details are updated accurately.
Asset recordsSalesforce (E360) and KACE labels reflect the final ownership.

Escalation and Recovery

Escalate instead of improvising through repeated failures.

Device will not boot to MDTReview BIOS and wired network path first. Do not continue until the boot method is reliable.
Post-image script or activation failsUse the manual recovery step once, then escalate instead of repeating the same failed flow.
DNS, VLAN, or asset ownership is unclearHold the handoff and resolve the record path before closing the ticket.
